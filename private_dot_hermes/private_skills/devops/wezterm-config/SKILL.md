# WezTerm Config Repo — Nightly / Bleeding Edge

Always-on rules:

1. Understand before changing. Read `wezterm.lua`, modules, feature registry first.
2. Check `@todo.md`, verify against live code.
3. Assume nightly `wezterm-nightly`. Upgrade deprecated APIs. Backward-compatible by default; gate new behavior behind feature toggle.
4. Feature toggle (`Features.register`) = source of truth. Load settings via `Features.get_custom_settings()` — never `require('config.user')` directly (that path is gone; state lives in `config/user.json`, read with `io.open`).
5. Zero comments on new code. No banners, no docstrings for internal functions. Only external API notes or legal notices.
6. Domain modeling: make invalid states unrepresentable. Use sealed types (boolean validation in `Features.set_enabled`/`apply_config`), smart constructors (`window-state` feature opt-in with `enabled = false`). Encode failures in return types (Result/Either) rather than exceptions or null. Flat static SPA > build steps.
7. FP / monadic side effects: pure functions, immutability, pattern matching. No defensive code masking real bugs — root-cause first.
8. Verify syntax after changes. No commit until explicitly told (`git` excluded from agent autonomy); when told, commit with a Conventional Commits subject scoped to the area (`feat(theme): ...`, `fix(config): ...`), keep the body to factual bullets with no narrative, one commit per coherent change, and never push unless asked.
9. Treat roast, audit, and issue claims as hypotheses. Compare each claim with current source and recent commits; classify it as stale, valid, subjective, or already fixed before editing. Vanity metrics (line counts, file counts, "too much machinery", theme taste) are always subjective — skip them; ship only where behavior is wrong, a supported built-in is duplicated, or a live runtime error exists.
10. Prefer nightly-native APIs over local reimplementations when they preserve behavior: `wezterm.serde.json_encode_pretty`, `wezterm.default_hyperlink_rules()`, `wezterm.column_width()`, and `wezterm.truncate_right()`.
12. Colour is theme data, never code: a scheme is a `themes/<id>.lua` file (role table + `wezterm` overlay + `config` overlay) plus one line in `themes/registry.lua`, and every switch is offered through the F2 command palette. Never re-introduce hex literals into `colors/*.lua` or the event modules. Depth: `references/theme-system.md`.
13. Legibility work changes the SIGNAL colour, not the identity colour: keep the theme's `foreground` unless the user asks for it, move the error/warning role instead, and choose values from measured WCAG contrast plus CIE76 ΔE rather than by eye. Blame the layer that emits the escape code — a TUI's own colour config or an LS_COLORS entry is often the cause, not the palette. Offer competing palettes as a rendered comparison the user can click, not as prose. Depth: `references/colour-legibility.md`.
11. Treat config reviews as privacy-sensitive: scan supplied text and repository metadata separately for email, secrets, local usernames/home paths, public handles, and person/address data; distinguish definite PII from possible detector matches and never reproduce raw email or secrets.
14. `README.md` is a second copy of facts that already live in code, and it drifts: it kept a Theme section pointing at `colors/custom.lua` and a hex table matching no live theme after the theme registry landed. Before editing a doc, map each claim to its source — feature names and defaults to the `Features.register` calls in `config/features.lua`, custom keys to `Features.CUSTOM_DEFAULTS`, the theme list to `themes/registry.lua`, hexes to the `roles` table in `themes/<id>.lua` — and correct the inaccuracy in the same pass. Rebuilding the hex table also doubles as a legibility audit, because `colors/theme.lua` validates only that each required role is a string.

Procedure:

1. Before quoting or forwarding supplied config content, run a privacy pass. Use OpenRouter labels for detected built-ins (`[EMAIL]`, `[PHONE]`, `[IP_ADDRESS]`, `[SECRET:<type>]`, `[PERSON_NAME]`, `[ADDRESS]`) and `[REDACTED]` for local usernames, home paths, or public handles when needed. Scan repository history/metadata separately; a blocked request does not reveal its exact trigger.
2. Read the supplied audit/roast, `todo.md`, `wezterm.lua`, feature registry, and target files fully. Map every claim to live source before changing anything.
3. Map module load order before editing: initialize runtime data before requiring modules that snapshot choices at load time.
4. `patch` for edits. `patch` is also the forced path for any file whose last read was paginated: `write_file` refuses the overwrite and reports the file as a "partial view" even when the read returned `truncated: false`, so apply the change region by region rather than re-reading to satisfy the guard. `write_file` is for new files and for existing small files whose backslash-bearing literals make `patch` unreliable (then read the file back and confirm the literals).
5. New feature: register in `features.lua`, implement, wire in `wezterm.lua`, opt-in (`enabled = false`).
6. Bug fix: root cause (e.g. `transparent_on == true`, override merge, regex `\\}`), not symptom patch. Delete local code when a supported WezTerm API replaces it.
7. For JSON read with `io.open`, call `wezterm.add_to_config_reload_watch_list(path)`. Persist runtime changes, roll back in-memory state on write failure, then reload from the event callback.
8. Set feature-backed config values explicitly in both states when WezTerm defaults would otherwise make disabling a feature ineffective (`enable_tab_bar`, `show_new_tab_button_in_tab_bar`, `automatically_reload_config`). Gate platform-specific actions when their domain only exists on that platform.
9. Verify, cheapest first, but know what each channel proves: (a) `wezterm --config-file <abs-path> show-keys` is a smoke test only — it has printed identical output for a config that was in fact broken, and it omits config-defined F-key bindings, so `Default key table` and absent F-keys prove nothing on their own; (b) strongest CLI probe: copy the repo to a scratch dir (`wezterm.config_dir` is the directory of the `--config-file` path, so requires resolve inside the copy), then `pcall(dofile, wezterm.config_dir .. '/wezterm.lua')` to run the REAL entrypoint and write assertions out with `io.open(config_dir .. '/probe.txt', 'w')` (config values, `#result.keys`, palette item briefs) — this catches module-load and wiring breakage that requires-inside-a-probe miss; (c) `wezterm.log_error` dumps, then grep the newest `$HOME/.local/share/wezterm/*-log-*.txt`; (d) palette fields and colour values are validated by NEITHER CLI path — only the GUI logs `Configuration Error: ...`, so reload (Ctrl+Shift+R, or let the watcher pick up the edit) and grep the newest `wezterm-gui.exe-log-*.txt`; a Configuration Error means WezTerm dropped the ENTIRE config, not just that one field. `error()`/`print` from a CLI-run config never surface. Ready-made probe: `templates/probe-config.lua`. Event-callback behaviour only executes inside a GUI process: launching a window is intrusive and killing it needs user consent, so ask the user to reload and read the log instead. Test input/output, not internal calls.

Pitfalls:

- `backdrops:initial_options()`: `transparent_on == true` (was `or true`); verify caller arguments too, because a corrected callee still yields transparent startup when caller passes `true`.
- `set_config_overrides()`: merge existing (`get_config_overrides()` first).
- Hyperlink regex: `\\}` not `\\)`; use `wezterm.default_hyperlink_rules()` when custom rules only duplicate built-ins.
- `user.json` loaded with `io.open` is not watched implicitly; add it to the reload watch list. Persist before reload, restore prior state on write failure, and reload from the event callback so a toggle is runtime behavior rather than persistence only.
- `config.command-palette` snapshots `backdrops:choices()` at require time; load backdrop images before requiring the palette or its selector has no choices.
- Feature flags with positive WezTerm defaults need explicit `false` assignments or their disable state is a no-op.
- `format-tab-title` `max_width` is cell width, not byte length; use `wezterm.column_width()` for comparisons and `wezterm.truncate_right()` for truncation.
- Gate command-palette/domain entries by platform, not only key bindings; otherwise non-native actions remain discoverable.
- `find_git_dir()`: `.git` file (worktrees) + `.git/HEAD`; don't restrict to `~/`.
- `WslDomain`: omit `username`/`default_cwd` — WezTerm already resolves the distro's default user and home. Hardcoding a local username or `/home/<user>` makes a public config machine-specific for no gain.
- User settings: `Features.get_custom_settings()` only.
- Blur: `window_background_opacity` < 1.0; `wayland_window_background_blur`.
- `front_end = 'OpenGL'`: `webgpu_*` dead; make conditional.
- Window-state persistence (`window-state` feature): persist size only — event callbacks pass a GuiWin, which has `get_dimensions`, `set_inner_size`, `set_position`, `maximize` but no `get_position`, so position cannot be read or restored. Save on `window-resized` with value-compare (not `update-status`, to avoid lag; no `close` event exists), skip saves while `dims.is_full_screen`. Restore via `mux.spawn_window()` → `gui_window()` → `set_inner_size`, deferred with `wezterm.time.call_after` so the cell-math spawn estimate cannot win. Depth: `references/window-state.md`, `references/theme-system.md`.
- `window:gui_window()` on a Window handed to an event callback raises "attempt to call a nil value (method 'gui_window')" on every focus/resize — `gui_window()` is a MuxWindow method (the inverse of `window:mux_window()`) and only exists on the object `mux.spawn_window()` returns.
- Regex/pattern lists duplicated between keybindings and the command palette drift: a typo fixed in one copy survives in the other. Keep one module (`utils/url-patterns.lua`) and require it from both.
- Patching Lua regex literals: `read_file` output is JSON-escaped, so backslash runs copied from it are doubled — `patch` refuses with an escape-drift error, and fuzzy matching can otherwise hide the mismatch. Anchor on backslash-free lines, or rewrite the small file with `write_file` and read it back to confirm the literal kept its `\(`.
- Never call `wezterm.glob` / `wezterm.read_dir` during config load: they are yield-capable and raise `attempt to yield across a C-call boundary` (inside `require`/`pcall`, and in the GUI loader), which drops the whole config. Discover variants from an explicit registry module that the theme/feature code requires — file-system discovery is the wrong tool here. Registry ids must equal the module name: renaming a theme file without updating the list logs `module 'themes.X' not found` and silently falls back to the default theme.
- Importing a palette from another tool fails on two fronts that only the GUI loader catches: `#RRGGBBAA` 8-digit hex is rejected (`failed to parse #00d4aa55 as RgbaColor` — convert alpha-bearing hex to `rgba(r, g, b, a)`, which parses for every field and honours alpha only in `selection_bg`/`selection_fg`), and write-ups name fields this build lacks (`scrollbar_thumb_hover` → `Configuration Error: ... is not a valid Palette field`, which drops the ENTIRE config). Validate against the GUI log (channel 9d) before calling a new palette live.
- Never remap the fixed part of the 256-colour ramp through `config.colors.indexed`: slots 16-231 are a fixed RGB cube that outside colour databases address by number, so mapping 16/17 to semantic colours makes LS_COLORS/vivid/lsd entries render their own absolute colours in an unrelated accent (an LS_COLORS `48;5;186;38;5;16` README highlight dropped to 1.07:1 and looked like a nushell bug). Omit `indexed` — WezTerm's stock ramp is the standard xterm one — or touch only slots no external tool addresses. Depth: `references/colour-legibility.md`.
- `wezterm.reload_configuration()` belongs in a key/palette callback, never in the config body: a probe that calls it during evaluation hangs the CLI until timeout.
- Probe booleans encoded as `act.Nop` / `act.DisableDefaultAssignment` are lossy — a `DisableDefaultAssignment` action on a key with no default binding is dropped from `show-keys` output, so `false` results look like missing lines instead of `false`. Prefer an `io.open` value dump; if you use the Nop channel, give every check a distinct key (`F13`+) and read absent lines as false.
- `colors.palette` is the resolved-roles accessor for the ACTIVE theme and the event modules snapshot it at require time: a theme switch takes effect by persisting the choice and reloading the config, not by mutating tables in place.
- The Palette converter reports one invalid field at a time and stops: fix, reload, re-read the log, repeat.
- Persisted-string settings (e.g. `custom.theme`): compare the requested value against the value read back from `user.json`, not against the in-memory snapshot, or re-selecting the fallback theme never repairs a stale id.
- A role/palette table whose entries no consumer reads is a landmine: before editing a colour, grep for the consumer and confirm the value reaches `config.colors`. In this repo the theme's explicit `wezterm.ansi`/`brights` arrays drive ANSI colours and the `roles` table drives the UI, so editing `roles.red` changes nothing on screen while `wezterm.ansi[2]` is what the terminal shows. Keep one source per value, or verify the edit end to end.
- Runtime errors are the highest-signal roast answer: grep the wezterm log for `ERROR` lines naming repo files. A feature can ship, look correct, and throw on every focus/resize event.
- A prose pass on the docs means STE, not a light edit: the user wants ASD-STE100 Simplified Technical English (skill `creative:simple-english`) and rejects em-dashes, en-dashes, and semicolons in prose — use a colon, a comma, or two sentences instead. Rewrite prose only; code blocks, JSON, paths, and identifiers are untouchable. Prove the boundary held by listing real changes with `git diff README.md | grep '^[+-]' | grep -v '^[+-][+-]'`, because a plain `grep -c` on the diff over-reports (context lines match too). `README.original.md` is the preserved upstream README: leave it alone unless asked.
- Theme `label` strings in `themes/*.lua` carry an em-dash and render in the F2 theme selector, and `colors/theme.lua` validates only presence and type of the required roles — so an em-dash cleanup of the docs does not reach them and no validator flags the leftover. Removing one is a code change that alters visible UI, so flag it for the user rather than editing it inside a documentation pass.
