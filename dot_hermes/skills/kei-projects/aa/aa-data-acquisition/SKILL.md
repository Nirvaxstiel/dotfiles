# AA Data Acquisition — how each source is obtained

The pipeline consumes **files under `data/sources/`** — never live endpoints at build time. Each source lands as a committed file; `_build_registry.py` reads raw files only (no circular dependency, no build-time network). Scriptable sources (AA public model catalog, OpenRouter, LiveBench, and Dirac via `_pull_sources.py`) are auto-pulled; `_pull_sources.py` also transforms the manually downloaded OpenLLM parquet. The keyed AA live API, scraped AA data, AA charts SVG/JSON-LD, and Arena are committed as source files.

For model-family assignment, use `release.slug` and `release.name` from the catalog row's model slug; do not attach a release-slug alias to a canonical model family, because historical releases can resolve to the same model ID. **There is NO vision/OCR image-chart source** — it was fully removed (see "Source removed" pitfall below); every AA benchmark metric now comes from the SVG scrape (#1A) and JSON-LD (#1B).

## User preferences (acquisition)
- **No vision / image parsing. No "voodoo."** The user rejected AA chart image-download + vision transcription outright: *"the images are fucked and are scuffed, they only let you download the visible window (disregarding the scroll)"* and *"pretty solid scraping without manual and vision capabilities and voodoo nonsense"*. Prefer structured export (JSON-LD, API, CSV, parquet) over any screenshot/OCR/manual-table path. If a metric only exists behind a chart image, tell the user to re-run the console query with that chart selected — do NOT fall back to vision.
- **Dedup only after proving values are genuinely different.** When two sources expose the "same" metric (e.g. AA's two Intelligence datasets), assert the overlapping slugs have identical values *before* collapsing to one. If they differ, they are different sources — keep both. This is a hard rule, not a suggestion.

## Per-source detail

### 1. AA scraped (primary) — external scraper
- HTML scraping of AA model pages (intelligence index, $/M, speed, output tokens, params, cost segments).
- Scraper lives **outside this repo**. Writes `aa/raw/` + `aa/enriched/`.
- Not automatable from here. Run scraper → then standard build.

### 2. AA live API (`aa_api_live.json`) — REST, keyed
- `GET https://artificialanalysis.ai/api/v2/data/llms/models`, header `x-api-key: <AA_API_KEY>`.
- Free-tier key (100 req/day). Key in Hermes `.env` as `AA_API_KEY` — **never hardcode** (read via `os.environ.get('AA_API_KEY')` or parse `.env`).
- Payload: `status`, `prompt_options`, `data[]` (572 models). Each has `slug`, `release_date`, `model_creator.name`, `evaluations{}` (16 scores: hle, gpqa, aime, aime_25, scicode, lcr, terminalbench_v2_1, …).
- Repro (pipe through `python -m json.tool` so the file is diff-readable — the API returns compact single-line JSON, which is impossible to `git diff`): `curl -s -H "x-api-key: $AA_API_KEY" <url> | python -m json.tool > data/sources/aa/aa_api_live.json`
- Used for: `release_date`, `creator` backfill, 16 live-AA benchmark axes.

### 2A. AA public model catalog — no-key identity fallback
- `_pull_sources.py` fetches `https://artificialanalysis.ai/leaderboards/providers?_rsc=hgvan` as a public Next.js React Server Components payload; it requires no API key.
- `aa/aa_public_model_catalog.json` stores the model records with `slug`, `release.slug`, `releaseDate`, and `creator.name`.
- The AA source builder resolves `release.slug` to the canonical family id and fills null `creator`/`release_date` fields only for models seeded by the chart/JSON-LD exports. It does not seed models or benchmark values.
- This is an internal website payload, not a stable API. Use the keyed REST API for evaluation scores; use the RSC catalog only for public identity metadata.

### 1A. AA benchmark charts — SVG scrape (method-2, PRIMARY) + JSON-LD fallback
- **AA chart "Download as image" is BROKEN for data** — it exports only the visible viewport and ignores scroll. Never use image downloads for AA metrics.
- **PRIMARY method (method-2 SVG scrape):** AA comparison pages render every chart as an inline **SVG** (recharts). A console snippet grabs each chart section (`[dir=ltr].scroll-mt-24`) → `{ svg, spans }`. The export `aa/aa_charts_export.json` is a JSON array (16 entries; scatter charts carry no `<a>`/value text and are skipped). Parser `data/sources/aa/_parse_charts.py` extracts `<a href="/models/{slug}">` + value `<text>` per chart, pairs by render order → clean `slug → value`. **No vision, no OCR, no manual transcription.**
  - **Scatter/over-time charts are NOT parsed for per-model data.** The file contains 10 additional charts (Intelligence vs Cost, Intelligence vs Context Window, Latency vs Speed, Intelligence vs Parameters, Time-to-First-Token over time, End-to-End Response Time over time, Openness vs Intelligence, etc.) that render as scatter/over-time plots. These have **zero `<a href="/models/{slug}">` links** — only `<circle cx= cy= data-chart-item-id=UUID>` points — so there is no way to map circles to model slugs without fragile text-label proximity matching. More importantly: every scatter chart's data is already sourced from other places (intel from JSON-LD, cost_per_task from JSON-LD, context_window from OpenRouter, params_b from OpenLLM, ttft/speed_tps from the AA live API). SVG extraction would duplicate existing values with no slug linkage and no new information. The parser correctly skips these — do NOT attempt to re-extract them. If AA adds a NEW bar chart with `<a href>` links, it will be picked up automatically by the title-based map; scatter charts remain unparsed by design.
  - **Pricing (#9) — SOLVED:** the chart title names the 3 series ("Cache Hit, Input, and Output"), matching the 3 `recharts-label-list` groups. Each value `<text>` has an `x` coordinate; aligning values to model columns by `x` (round to per-model band) yields per-model `cache_hit_price` / `inp_price` / `out_price`. Validated vs live API (`gpt-oss-20b` 0.05/0.2, `claude-opus-4-8` 5/25 — exact). Parsed by `_parse_pricing()`. All 12 gpt-5.6 models gain pricing.
  - **Chart-to-key mapping is TITLE-BASED, not index-based.** `_CHART_TITLE_MAP` keys off `spans[0]` (the chart title) → logical key. This survived the 2026-07 AA redesign that moved the main Intelligence Index to index 0 and DELETED the standalone Coding Index + Cost to Run bar charts. An index-based map would have silently mis-mapped the moved Intelligence Index onto `coding_index` (corrupting it with intel data); the title match instead skips removed charts. The parser also drops any chart that parses to 0 rows, so a removed chart leaves NO empty key. If AA renames a chart title, update the matching substring in `_CHART_TITLE_MAP` — do NOT reintroduce positional indexing.
- **Fallback (JSON-LD console export):** AA pages also embed `Dataset` JSON-LD. Console query → `aa/aa_jsonld_export.json`. Ingested as Step 0b — fills ONLY fields method-2 didn't capture. See `references/aa-jsonld-acquisition.md` for the field map.
- The SVG/JSON-LD merges into the **same `aa` source** as scraped/live-API (fill-nulls-only) — do NOT create a separate stream.

### 4. OpenRouter — REST, public
- `GET https://openrouter.ai/api/v1/models` (no auth). `_pull_sources.py` → `openrouter_models.json`.
- Key fields: `pricing.prompt`, `pricing.completion`, `pricing.input_cache_read/write`, `context_length` (→ `context_window`).
- Repro: `python data/_pull_sources.py`.

### 5. LiveBench — CSV, pinned
- GitHub raw CSV + JSON, pinned snapshot `2026_01_08`. `_pull_sources.py` downloads both.

### 6. OpenLLM v2 — parquet, manual
- **Not fetched by script.** Download `openllm_v2.parquet` externally → place at `data/sources/`. `_pull_sources.py` reads it → `openllm_aa_subset.json` (keyword-filtered).
- Repro: download parquet first, then `python data/_pull_sources.py`.

### 7. Dirac.run — scriptable HTML-table fetch (`scripts/fetch_dirac.py`)
- **NOT manual** — the page `https://dirac.run/posts/cache-hit-rates-agents` renders the full table as a real HTML `<table>` (the "Small Model Grift" subset table is smaller; the #the-full-table anchor precedes the 398-row table). Fetch via `urllib` (NOT `curl` — raw `curl` to this host trips the agent command blocklist; `urllib.request` in a python step is fine), locate the table after the `#the-full-table` anchor, parse `<tr>/<td>`, strip `$`/`,`/`%`, write JSON.
- 398 rows (was 276 before the 2026-07 refresh). Shape: `{model, provider, eff_input_price, eff_output_price, cache_hit_rate}` — **exact** keys the pipeline's `get_dirac_models` expects. Do NOT rename fields.
- Pitfall: there are 4 `<table>` elements; the "Small Model Grift" one (4 rows) also matches a "cache" keyword — pick the table AFTER the `#the-full-table` anchor (it's the 398-row one). A wrong-table grab yields 4 rows with `provider` = a number.
- Semantics: observed % of input served from prefix cache — **distinct** from AA's `cache_hit_price` ($/Mtok read price). Never conflate.
- Repro: `python scripts/fetch_dirac.py` (writes `data/sources/dirac/cache_hit_rates.json`). Run on new snapshot.

### 8. Chatbot Arena — manual JSON
- Download leaderboard JSON → `arena_code.json` / `arena_text.json` (each `meta` + `models[]`). Not fetched by any script.

## Pitfalls
- **AA chart image download is broken** — it captures only the visible viewport, ignores scroll. Use the JSON-LD console export instead (see `references/aa-jsonld-acquisition.md`).
- **Removing a source = delete it everywhere, NO tombstones.** When a source (or any feature) is removed, strip it from the matrix, the per-source detail section, repro checklist, schema docs (viz/README `confirmed_scraped` etc.), README step lists, and the source files — then RENUMBER the matrix so there's no gap. The user explicitly rejected leaving a `- REMOVED` / `DEPRECATED` marker in the docs: *"we should remove it from the markdowns, not just add a - 'REMOVED'. lol. dont confuse yourself and users later on as we work more on this."* A tombstone is a future trap — the next session won't know if it's live or dead. If the removal needs justification, say it ONCE in a code commit message, not in the docs.
- **Source removed (2026-07): the AA image / vision-OCR chart source is GONE.** `data/sources/aa/img/` (incl. `aa_img_models.json`), `aa_scrape_progress.json`, `step_aa_img` + `step_scrape_progress` in `_build_registry.py`, `_build_aa_image_axes` in `_build_axes.py`, the 12 `aa_img.*` axis projections + `AA_IMG` source/meta in `_build_dashboard_data.py`, `aa_img` in `project_axes.py`, `AA_IMG_NAME_MAP` + `aa_img_name_to_canonical` in `_canonical.py`, the `AA_IMG` enum in `_domain/_base.py`, and the `confirmed_scraped` field were all deleted (commit `425fd64`/`38189f4`). Why safe: aa_img was ingested into `model_registry.json` (60 models) + `axes_catalog.json` (12 AA_IMG axes) but **never reached `processed.js`** — 0 viz references. Every aa_img metric (Omniscience Index, Omniscience Hallucination Rate, Briefcase Elo/Analytical/Presentation, Agentic Index, Coding Index, Openness) is a strict SUBSET of what the SVG scrape (#1A) and JSON-LD (#1B) already capture (confirmed in `_build_axes.py`: SVG covers Coding 58, Briefcase Elo 35, Omniscience Hallucination 104, …). So removal lost zero product value. If asked to "re-add image charts," STOP — the metrics already exist via #1A/#1B; only re-add if a genuinely NEW metric appears that neither covers.
- **Regenerate committed artifacts after any source/axis change.** Removing/adding an axis or source changes `model_registry.json`, `axes_catalog.json`, `processed.js`. Run the offline build (`PYTHONPATH=data python -c "import data._pipeline as p; p.build_from_cache()"`) to regenerate them, then `git` the new artifacts in the same commit as the code change. The determinism test compares two FRESH runs against each other (not HEAD), so a code change that alters output won't fail it — you MUST regenerate the committed artifacts or the repo is inconsistent. Verify before commit: `grep -c aa_img data/model_registry.json data/axes_catalog.json data/processed.js` should be `0 0 0` (or whatever the removed token is).
- **VALIDATE a scraped/exported file's SHAPE before it overwrites a committed source.** A fresh export can be malformed and silently nuke metrics. When the user hands you a new scrape (e.g. `13jul2026_svg_scraped.json`), diff its structure against the committed file BEFORE copying:
  - JSON-LD export: assert it's a list of `Dataset` objects with the same `name` set as the committed one, and that each dataset's `data[]` is non-empty. (If the `name` set shrank or a dataset's `data` is empty, metrics will drop silently.)
  - SVG scrape export: assert each entry's `svg` contains `recharts-surface` (the real chart surface). **A broken scrape produces `lucide` UI-icon `<svg>` blocks instead** — all 16 entries being `class="lucide lucide-*"` means the capture grabbed page icons, not the chart `<svg>` blocks. The durable fix is the console selector `svg[role]` (NOT `svg`): post-2026-07 AA redesign, bare `svg` matches the page's lucide UI icons. A correct capture yields `sum('recharts-surface' in e['svg'] for e in d) == len(d)` (16/16). Overwriting `aa_charts_export.json` with a broken (lucide) file would wipe EVERY AA chart metric from the dashboard with zero error. KEEP the last good committed SVG and tell the user to re-scrape.
  - Shape check recipe: `python -c "import json; d=json.load(open(f)); print(type(d).__name__, len(d)); [print(e.get('name')) for e in d]"`. For SVG: `sum('recharts-surface' in e['svg'] for e in d)` should equal `len(d)`.
  - Copy valid files with `cp`; never `git mv`/overwrite blindly. Confirm byte-identical after copy with `cmp`.
  - **RECURRENCE:** this broken-lucide pattern happened TWICE (13jul2026 AND 23jul2026 exports were both lucide-icon garbage). If the user says "I fixed the SVG charts, re-look at it," DO NOT trust the claim — re-run the recharts-surface count first. Both times the user believed they'd fixed it; both times the file was still page icons. Re-verify before overwriting `aa_charts_export.json`.
- **Upstream data drift breaks tests that pin a specific model.** When a test asserts `model["slug"] == "X" has field Y`, and the new AA export no longer includes X's data (e.g. `gpt-5-6-luna-medium` lost its `cost_seg_reasoning` in a refresh — the model simply isn't in the Cost-per-Task/Pricing datasets anymore), the test fails even though the CODE is correct. Distinct from a regression: confirm the field is still populated for OTHER models (`node -e "...models.filter(m=>m.cost_seg_reasoning!=null).length"` → 37 models had it). Fix: repoint the assertion to a model that still has the data (e.g. `claude-opus-4.8`), keep the SAME intent. Don't revert the data refresh to satisfy a stale test.
- **AA chart redesign breaks the chart-parse tests (count + value pins).** When AA reorders/removes charts (2026-07: moved Intelligence Index to index 0, deleted the standalone Coding Index + Cost to Run bar charts), `test_aa_charts_parse.py` assertions pinned to the OLD world break: counts shift (intel 106 to 107, briefcase 35 to 36, omniscience 104 to 105, time_per_task 53 to 62, pricing 94 to 95) and per-model values change (briefcase claude-fable-5 1764/1592 to 1600/1346 — a genuine AA value update). Fix pattern: (a) re-run the parser and read the ACTUAL current rows/counts/values from its output — never just bump the number; (b) DELETE the TestCodingIndex + TestCostToRun test classes entirely, because those charts no longer exist in the file (the metrics now come from JSON-LD and are tested under test_jsonld_aa_source.py); (c) update surviving counts/values to the verified-actual ones. The parser is title-based and skips removed charts, so it correctly emits no coding_index/cost_to_run key — the test must assert their ABSENCE, not their presence. Don't revert the data refresh to satisfy a stale test; the data change is real.
- **AA_API_KEY is in Hermes `.env`, not the repo.** A missing key = empty `aa_api_live.json` = no `release_date`/live benchmarks. Read env, never commit the literal.
- **Dirac ≠ AA cache.** Dirac is observed hit %, AA is cache *price*. Mixing them is a semantic bug.
- **Never let a source step CREATE a record for an id it can't find.** `step_dirac` used to `setdefault()` a nameless shell record per unmapped id; combined with a `DIRAC_NAME_MAP` whose targets had drifted to the dashed id convention (`glm-5-1` while AA now emits `glm-5.1`), that produced **57 shell models next to the real ones** and split one model's provider rows across both ids (`glm-5.1` held 19 of 25). Rules that fixed it, apply to any future source: (a) resolve the name through the canonical map, (b) attach only to a record that already exists — exact id first, else a UNIQUE dot/dash-normalized match, else skip and count, (c) print the skipped ids in the build summary so drift surfaces instead of silently forking the id space. Coverage went 30 → 61 models and the model count dropped 2299 → 2268.
- **A source's resolution step must run after the sources that create records.** `step_dirac` ran second (right after AA), so ids only known from OpenRouter/LiveBench/OpenLLM could never receive provider rows. It now runs after `step_openrouter` — ordering is part of correctness, not cosmetics.
- **When a hand-maintained map target drifts, fix the map AND keep a normalized fallback.** Fixing the 11 stale `DIRAC_NAME_MAP` targets is data hygiene; the unique-normalized fallback is what keeps the next AA rename from forking the id space again. Verify a map target with the registry payload, not the name: the real model has AA fields, the drifted id is a nameless shell with only dirac rows.
- **`PYTHONPATH=data` is required for any `python -m data.<script>` run.** `_canonical.py`/`_build_registry.py` do bare `from _result import ...`; without it you get `ModuleNotFoundError: No module named '_result'`. `python data/_pull_sources.py`-style invocation works because the script's own dir lands on `sys.path`.
- **`_merge_fill_nulls` MUST recurse into nested dicts.** It merges scraped/charts/JSON-LD into an existing record fill-nulls-only. The original implementation only recursed ONE level deep — so nested `benchmarks.aa` / `pricing.aa` fields (e.g. `aa_math_index`, `cost_segments`) were silently dropped when a charts-seeded record (created via `ensure()` with the full None schema) was merged with a scraped record. This stayed hidden while scraped models were hard-assigned; it surfaced the moment charts-seeded records entered the merge path (live-AA 16 benchmarks + cost_segments regressed to 0). Fix: recurse (`_merge_fill_nulls(ev, val)`) instead of a single-level `for k2,v2` loop.
- **One AA source.** SVG-scrape (method-2, Step 0), JSON-LD (Step 0b), scraped, and live-API all merge into `aa` (fill-nulls) — never split AA into separate streams. Method-2 wins on overlap (it's the superset).
- **JSON-LD loader: the scraped-base loop must MERGE, not overwrite.** `get_aa_models` seeds models from JSON-LD first (Step 0), then the scraped loop (Step 1) previously did `all_models[cid] = {...}` — a *hard replace* that wiped any JSON-LD-only field (omniscience_hallucination_rate, etc.) on existing models. Fix: if `cid in all_models`, call `_merge_fill_nulls(existing, scraped)` (existing non-null wins) instead of replacing. New slugs (e.g. gpt-5-6-*) are unaffected since they aren't in the scraped set.
- **JSON-LD file location:** committed INSIDE the repo at `data/sources/aa/aa_jsonld_export.json` (renamed from the ad-hoc `jsonified-artificialanalysis-data.json` that lived one level above). Loader resolves `os.path.join(aa_dir, "aa_jsonld_export.json")`. Copy a fresh export there on each refresh.
- **JSON-LD export often arrives Markdown-fence-wrapped.** A console `copy(JSON.stringify(out))` can land in the file as `` `[{...}]` `` (leading+trailing backtick) instead of bare JSON. The loader does `json.load` directly, so a fenced file throws `Extra data: line 1 column 37697` (the trailing backtick). When copying a fresh export: strip BOTH backticks (`raw.strip().strip("`")`) and pretty-print (`json.dump(indent=2)`) so the committed file is valid + diff-readable. A 23jul2026 export hit exactly this — first `json.load` failed until both ends were stripped.
- **`creator` casing is normalized at BUILD time, not in comparisons.** `data/_canonical.py::normalize_creator()` (curated `_CREATOR_CANON` map keyed case-insensitively + strips the `~` parent-org prefix, Title-Case fallback) is applied at every `creator=` assignment in `_build.py` and `_build_registry.py`. So `google`/`Google`/`~google` all collapse to `Google`; comparisons/legend grouping are case-consistent by construction. Do NOT add case-insensitive comparison logic in the viz — the data is already canonical. If a new creator surfaces with a raw variant (e.g. `Kimi` from the live API), add it to `_CREATOR_CANON` if you want a specific display form, and to `viz/_shared.js` `CREATOR_COLORS` so `test_all_creators_have_colors` stays green (runtime falls back to a hash color but the contract test wants a curated hue).
- **Re-pull the live API when a JSON-LD-only model needs a sourced `creator`.** A model launched the same day (e.g. `kimi-k3`, 2026-07-16) may be absent from the committed `aa_api_live.json` but present in a fresh pull, with `model_creator.name` + `release_date`. Don't wing the vendor — re-run the curl to overwrite `aa_api_live.json` before the build. See `aa-api-live-fill` Pitfalls for the full recipe.
- **JSON-LD has a non-Dataset trailing entry.** The array's last element is `{"@type": "FAQPage", "data": []}` (site boilerplate). Dataset-parsing code must skip entries whose `@type != "Dataset"` (don't assert all entries are Dataset).
- **Seed NEW models with the FULL schema (all keys None), not a partial dict.** When `ensure(slug)` creates a base record for a JSON-LD-only model (one NOT in the scraped set), initialize `pricing.aa` and `benchmarks.aa` with EVERY key the downstream overlays touch, set to `None`. Downstream steps (`_overlay_enriched`, `_overlay_aa_api`) do direct `p["cache_hit_price"]` key access — a partial dict (e.g. only `{cost_segments: ...}`) KeyErrors there. Corollary: once you pre-populate the full schema, any `if key not in dict` guard that was meant to detect "unset" must become `if dict.get(key) is None` — otherwise it never fires (the key already exists as None) and the JSON-LD value gets dropped. - **Parsing grouped recharts bars with NO sub-labels — use x-band alignment.** When a chart's values carry no input/output/cache label (e.g. Pricing #9), the values live in per-series recharts-label-list groups; each value text has an x coordinate. Split into the 3 groups, take the complete group as the reference x-axis, compute per-model spacing (max_x - min_x)/(n-1), then map each value to idx = round((x - min_x)/span). This recovers per-model cache_hit_price / inp_price / out_price with zero guessing. Series ORDER is given by the chart TITLE. Full recipe in references/svg-chart-scrape.md.

- **`cost_per_task` = per-task cost, NOT full-benchmark-run cost.** The JSON-LD "Cost to Run Artificial Analysis Intelligence Index" dataset reports the cost to run the ENTIRE intelligence index as one job (full-index token volume) — $333 for qwen3-6-35b, $275 for gpt-5-6-luna-high. That is 100-1000x the real per-task cost and must NEVER be summed into `cost_per_task`. `cost_per_task` derives ONLY from (a) the JSON-LD "Cost per Task" dataset (`costPerIntelligenceIndexTask`, sane max ~$2.75) and (b) `aa_cost_breakdown.json` `total_cost_per_task_usd` (Step 3, max ~$2.29). The "Cost to Run" dataset's 5 segments (`answerCost`/`reasoningCost`/`cacheReadCost`/`cacheWriteCost`/`nonCacheInputCost`) populate `cost_segments` (descriptive) — their sum is the full-run cost, do NOT assign to `cost_per_task`. Regression signal: any model with `cost_per_task` > $5 (or a radial cost-eff axis whose apex > $5) means the full-run dataset corrupted per-task sourcing. NOTE: the user's observed "$50/task" on the radial was a SEPARATE artifact — the axis MAX label computed `1/minCost` (=50) and rendered it as "$50/task"; that's a label bug, fixed independently of the data bug.
- **Radial cost-eff axis: never render `1/minCost` as a USD label.** The provider-archetypes cost axis normalizes as `cost_raw = 1/cost_per_task` (cheaper = larger radius = better). A naive "show the max at the apex" label computed `1 / Math.min(allCost)` and printed it as `fmtUSD(50) = "$50/task"` — which reads as "max cost $50" and implies high cost scores well. That was the user's "$50/task" observation; it is a LABEL bug, NOT the data bug above. Correct pattern: the apex label shows the **normalized efficiency score** (0–100, bigger=cheaper=better) and the real `$/task` lives in the panel stats row (`$X/task (NN eff)`). If you see a radial apex showing a dollar figure derived from an inversion, it's almost certainly this mistake — show the score, keep the raw $ in the stats.
